# 体重ダッシュボード 設計書

- 作成日：2026-11-05
- 状態：レビュー待ち
- 対象：毎朝の体重を自動で記録し、目標までの進み具合を「着地アプローチ表示」の計器盤ページとiPhone通知で確認する仕組み

> このリポジトリは公開されている。実際の体重・目標体重・チェックポイントの値は、この文書にもコードにも書かない。値はスプレッドシートの「設定」シートにだけ置く。この文書の数値例はすべて架空の値。

---

## 1. 目的

- 体重計で測るだけで、記録・計算・表示までが自動で終わるようにする。
- 「目標日に目標体重へ着地できるか」を、測った直後とページを開いたときにひと目で判断できるようにする。

### 1.1 成功の条件

1. 体重計に乗ってオムロン コネクトを開いて閉じるだけで、手入力なしに記録される。
2. 閉じてから数秒以内に、要約がiPhoneに通知される（6.3の条件つき）。
3. ホーム画面のアイコンからページを開くと、今日の体重・目標ラインとの差・予測・グラフが表示される。
4. 体重データはiPhoneと自分のGoogleアカウントの外に出ない。

### 1.2 範囲外

- メールでのレポート送信（検討の結果やめた。理由は8.1）
- 体脂肪率など体重以外の値
- このリポジトリのIRON LOGアプリ（`index.html`）との連携
- 複数人での利用

---

## 2. 全体構成

```
体重計 ─Bluetooth→ オムロン コネクト ─公式連携→ iPhoneのヘルスケア
  → ショートカット（オートメーション：オムロン コネクトを閉じたとき・確認なしで実行）
      │ 直近14日分の体重を送信
      ▼
  ① 受け取り口（Apps Script「ingest」・誰でもアクセス可＋合言葉）
      ├ スプレッドシート「体重ログ」に日付ごとに上書き保存
      └ 要約の文字を返す → ショートカットが通知に表示（B）
  ② 計器盤ページ（Apps Script「dashboard」・自分だけ閲覧可）
      └ 開くたびにシートを読んで計算し、表示する（A）
```

- 時刻指定の実行（トリガー）は使わない。
- ①と②は別のApps Scriptプロジェクトにする。理由は9.1。
- 計算部分 `Metrics.js` は①と②で同じファイルを使う。

## 3. データの取り込み

### 3.1 iPhone側

| 部品 | 設定 |
|---|---|
| オムロン コネクト | ヘルスケア連携をオンにする（コンテンツ → コンテンツ追加 → ヘルスケア → 連携設定） |
| オートメーション | きっかけ：「App」→ オムロン コネクト →「閉じたとき」。「確認なしで実行」（iOS 17以降） |
| ショートカットの中身 | 下の手順 |

ショートカットの手順：

1. 5秒待つ（オムロン コネクトがヘルスケアに書き込み終わるのを待つため。長さは実機で調整）
2. ヘルスケアサンプルを検索（種類：体重、開始日：過去14日以内、並べ替え：開始日の新しい順、上限なし）
3. 各サンプルを `YYYY-MM-DDTHH:mm,体重kg` の1行にする（単位はkgに指定）
4. 改行でつないで1つのテキストにする
5. 「URLの内容を取得」：方法POST、本文はフォーム形式で `token`（合言葉）と `samples`（4のテキスト）
6. 返ってきた文字を「通知を表示」で出す

**時刻ではなく「閉じたとき」に動かす理由**：iPhoneのロック中はヘルスケアのデータを読めないため。ロック中に読もうとすると「Protected health data is inaccessible」で失敗する、と報告されている（参考資料 R1〜R3）。アプリを閉じた瞬間なら、必ずロック解除されている。

**毎回14日分を送る理由**：送信に1回失敗しても、次に成功したときに抜けた日が自動で埋まる。

### 3.2 受け取り口（①ingest）の仕様

- 入口：`doPost(e)`。予備として `doGet(e)` も同じ処理を受け付ける（6.3の予備策）。
- 入力：`e.parameter.token`、`e.parameter.samples`
- 処理：
  1. `token` がスクリプトプロパティ `INGEST_TOKEN` と一致しなければ、何も書かずに `ERROR: 合言葉が違います` を返す。
  2. `samples` を1行ずつ読む。次の行は捨てる：形式が違う／体重が30〜200kgの範囲外／未来の日時（今から1時間より先）／60日より前。行数が100を超えたら先頭100行だけ使う。
  3. 日本時間の日付ごとに、その日いちばん早い時刻の測定を1つ選ぶ。
  4. 「体重ログ」に書く。その日の行がなければ追加する。すでにある行は、新しい測定の時刻が同じか早ければ上書きし、遅ければそのままにする。書き込み中は `LockService` で同時書き込みを防ぐ。
  5. 書き込み後のデータで要約（6.2）を作り、`ContentService` で文字として返す。
- 返す内容：要約の1行。データは返さない。

### 3.3 1日1値のルール

その日いちばん早い時刻の測定を、その日の体重とする。朝に測る前提のため。

## 4. スプレッドシート

1つのスプレッドシートに次の2枚のシートを置く。①と②は、スクリプトプロパティ `SHEET_ID` でこのスプレッドシートを開く。

### 4.1 「体重ログ」

| 列 | 内容 | 例（架空） |
|---|---|---|
| A 日付 | `yyyy-MM-dd`（日本時間） | 2026-11-04 |
| B 体重kg | 数値 | 71.6 |
| C 測定時刻 | `HH:mm` | 07:12 |
| D 受信日時 | `yyyy-MM-dd HH:mm:ss` | 2026-11-04 07:13:05 |

日付の古い順に並べる。手で直してもよい。

### 4.2 「設定」

A列に項目名、B列以降に値を書く。iPhoneのスプレッドシートアプリからでも直せる。

| A | B | C | 説明 |
|---|---|---|---|
| 目標日 | 2026-12-05 | | 着地する日 |
| 目標体重 | 70.0 | | 着地する体重（例は架空） |
| 開始日 | 2026-10-11 | | グラフの左端・進捗の起点 |
| チェックポイント | 2026-11-01 | 72.0 | 何行でも書ける（例は架空） |

## 5. 計算（`Metrics.js`）

`今日` は、ページを開いた日、または受け取り口が動いた日（日本時間）。`D(日付)` はその日の体重（3.3のルールで1日1値）。

| 項目 | 定義 |
|---|---|
| 今日の体重 | `D(今日)`。なければ直近の測定値を使い、その測定日を添える |
| 前日比 | 上の値 − その前に測った日の値 |
| 7日平均 `A7(d)` | `d−6`〜`d` の7日間に測った値の平均。測った日が4日未満なら「なし」 |
| 前週差 | `A7(今日) − A7(今日−7)`。どちらかが「なし」なら「なし」 |
| 目標ライン `T(d)` | 「チェックポイントを日付順に並べたもの＋(目標日, 目標体重)」を順に直線で結んだ線。最初の点より前は、最初の区間の傾きで延ばす。チェックポイントが0件のときは、開始日以降で最初に測った値から目標へ直線を引く |
| 目標ラインとの差 | `A7(今日) − T(今日)` |
| 状態 | 差が0以下なら「順調」、0より大きければ「要注意」、差が「なし」なら表示しない |
| 直近1週間のペース | 前週差（kg/週） |
| 直近4週間のペース | `(A7(今日) − A7(基準日)) ÷ ((今日 − 基準日) ÷ 7)`。基準日は「今日−28日」と「A7が初めて出る日」の遅い方 |
| 遅い方のペース | 上の2つのうち大きい方（＝減りが遅い方）。片方しかなければその値 |
| 目標日の予測 | `A7(今日) + 遅い方のペース × (残り日数 ÷ 7)` |
| 必要な週ペース | `−(A7(今日) − 目標体重) ÷ (残り日数 ÷ 7)`。残り日数が0以下なら「なし」 |
| 進捗 | `(T(開始日) − A7(今日)) ÷ (T(開始日) − 目標体重)` を0〜100%に収めた値 |
| 残り日数 | 目標日 − 今日 |
| 未測定の日 | 今日−6〜今日のうち、測定がない日 |

- 計算は細かい桁のまま行い、表示のときだけ丸める。体重・差は小数1桁、ペースは小数2桁。
- 日付は `yyyy-MM-dd` の文字列で扱い、日数の差は日本時間の日付から計算する（タイムゾーンのずれを防ぐため）。
- `Metrics.js` はApps ScriptとNode.jsの両方で動く普通の関数だけで書く。最後に `if (typeof module !== 'undefined') module.exports = {...}` を置き、テストから読み込めるようにする。

**計算例（架空）**：チェックポイントが11/1・72.0kg、目標が12/5・70.0kgの場合、目標ラインは1日あたり約0.0588kg（週0.41kg）ずつ下がる。11/4の目標ラインは約71.8kg。

## 6. 表示

### 6.1 計器盤ページ（②dashboard）

#### 見た目の考え方「着地アプローチ表示」

- 減量を、目標日・目標体重への「降下と着地」に見立てる。
- 色は飛行機の計器（グラスコックピット）の決まりにならう。マゼンタ＝たどる進路（目標ライン）、シアン＝計測値（7日平均・予測）、緑＝正常、アンバー＝注意（参考資料 R9。本文は未確認）。
- 目立たせる要素は「目標ラインとの差の計器」1か所だけ。ほかは静かに整える。

#### 色

| 名前 | 値 | 用途 |
|---|---|---|
| page | `#000000` | ページの背景 |
| panel | `#0A0F1A` | パネルとグラフの背景 |
| line | `#1C2636` | パネルの枠・区切り線・グラフの横線 |
| text | `#EAF0F7` | 主な文字 |
| sub | `#8592A6` | ラベル・軸の文字 |
| faint | `#4E5A6E` | 補足・目盛り |
| dot | `#5B6779` | 日々の体重の点 |
| cyan | `#38E1FF` | 7日平均・予測・今日の点・計器の◆ |
| magenta | `#FF4FD8` | 目標ライン・チェックポイント・着地点 |
| green | `#3CF29A` | 順調・体重が減った前日比 |
| amber | `#FFB547` | 要注意・体重が増えた前日比・未測定の印 |

#### 文字

- 書体：`-apple-system, "SF Pro Display", "Hiragino Sans", "Noto Sans JP", sans-serif`。外部のフォントは読み込まない。
- 今日の体重：80px・太さ200・字間−0.04em
- 計器パネルの数字：32px・太さ300・字間−0.02em
- ラベル：12px。補足：12px
- 数字にはすべて `font-variant-numeric: tabular-nums`

#### 配置（上から）

1. **上部の行**：左に今日の測定日時（例「11/5 木　07:12 計測」。今日の測定がなければ直近の測定日時）、右に「着地まで T−30 日」（残り日数。T−の数字はマゼンタ）
2. **ヒーローパネル**：
   - 「今日の体重」と、右上に前日比（▲アンバー／▼緑）
   - 体重の大きな数字
   - 目標ラインとの差の計器：±1.0kgを全幅とする横の目盛り。中央のマゼンタの線が目標ライン、◆（シアン）が現在の7日平均の位置。左が軽い、右が重い。上に「−0.1kg　順調」
3. **計器パネル（2×2、細い線で区切る）**：7日平均（シアン・前週差）／目標日の予測着地（遅い方のペース）／必要な週ペース（残り日数と残りkg）／進捗（%と細いバー）
4. **グラフパネル**（下の「グラフ」の表のとおり）
5. **注意メモ**：未測定の日があるときだけ、アンバーの●と「11/2は未測定。7日平均は測った日だけで計算しています。」
6. **フッター**：「スプレッドシートを開く」リンク

#### グラフ（ページ内にSVGで描く）

| 要素 | 見た目 |
|---|---|
| 期間 | 開始日〜目標日。今日より先は目標ラインと予測だけ |
| 日々の体重 | dot色の点（直径4px）、線でつながない |
| 7日平均 | シアンのなめらかな曲線（太さ3px） |
| 目標ライン | マゼンタの丸い点の点線（太さ1.5px） |
| 予測 | 今日の7日平均から目標日の予測値まで、シアンの破線（不透明度70%）。終点は白抜きの丸 |
| チェックポイント・着地点 | マゼンタの点。panel色の縁で線と重なっても見えるようにする |
| 今日の点 | シアンの点＋panel色の縁＋値のラベル |
| ラベル | 今日の7日平均、「着地 70.0」「予測 69.8」（例は架空）だけに付ける |
| 縦軸 | 右側。表示期間の体重・7日平均・目標ライン・予測の最小〜最大に±0.5kgを足し、0.5kg単位に丸めた範囲。目盛りは1kgごと・小数1桁 |
| 横軸 | 開始日・中間の2点・目標日を「月/日」で表示 |
| グリッド | 横線だけ（line色）。縦線なし |
| 凡例 | 上部に「体重・7日平均・目標ライン・予測」 |
| 大きさ | 幅はパネルいっぱい、高さ240px |
| 操作 | 指でなぞると縦の補助線と、その日の日付・体重・7日平均・目標ラインを表示する |
| 動き | 読み込み時に7日平均の線を一度だけ描く。iPhoneの「視差効果を減らす」がオンなら描かない |

#### ページの技術条件

- `HtmlService` のテンプレートで作る。計算は `doGet` 側で行い、結果をJSONでページに埋め込む。描画はページ内の短いJavaScriptで行う。
- 外部のファイル（フォント・ライブラリ・画像）は読み込まない。
- `addMetaTag('viewport', 'width=device-width, initial-scale=1, viewport-fit=cover')` を付ける。
- データがないとき：「まだ記録がありません。オムロン コネクトで測ってアプリを閉じると、ここに表示されます。」
- シートが見つからない・設定が足りないとき：何が足りないかと直し方を表示する（例：「設定シートに目標日がありません」）。

### 6.2 通知（B）の要約

受け取り口が返す1行。ショートカットがそのまま通知に出す。

`71.6kg ▲0.3｜目標ライン −0.1 順調｜予測 69.8（T−30）`（数値は架空）

- 今日の測定がまだないときは、直近の値と測定日を出す。
- 7日平均が「なし」の項目は省く。

### 6.3 通知の前提と予備策

- Apps Scriptの受け取り口は、POSTに対して別のURLへの転送（302）を返す。転送先は同じ処理結果の文字を返す（参考資料 R7・R8）。
- ショートカットがこの転送をたどって文字を受け取れるかは未確認。
  - **書き込み**：転送の前に終わるので、記録は残る。
  - **通知が出ない場合**：まずGETで送る方式（`doGet` で同じ処理）を試す。それでも読めなければ通知（B）はやめて、ページ（A）だけにする。

## 8. 決めたことと理由

### 8.1 メールをやめた理由

- iPhoneのGmailはダークモードで色を反転するため、暗いデザインが崩れるおそれがある（参考資料 R4〜R6）。
- メールには、`getBlob()` で画像にしたグラフしか載せられない。そのうえ、点線などが画像に出るかが未確認だった。
- ページなら、どちらの問題もない。測った直後の確認は通知（B）で代わりになる。

### 8.2 データの取り込み方法

オムロン コネクトには、個人が使える公開APIが見つからなかった（参考資料 R10・R11）。公式機能だけでつなげる、ヘルスケア経由の方法を選んだ。非公式の方法（オムロンの内部の通信先に、メールアドレスとパスワードでログインする）は採らない。

## 9. セキュリティとプライバシー

### 9.1 公開範囲を分ける

| | ①ingest | ②dashboard |
|---|---|---|
| 実行するユーザー | 自分 | 自分 |
| アクセスできる人 | 全員（ショートカットはGoogleにログインできないため） | 自分のみ |
| できること | 書き込みと、要約1行を返すこと | 表示 |

- ①には、データの一覧を返す機能を置かない。
- ②を別のプロジェクトにするのは、①と同じプロジェクトに置くと、①のURLから体重が見えてしまうため。

### 9.2 その他

- 合言葉が違う・値が範囲外などの要求は記録しない（3.2）。
- 体重データの通り道は、iPhone → 自分のGoogleアカウントだけ。外部のサービスやライブラリは使わない。
- テストデータは架空の値だけを使う。実際の体重・目標値はリポジトリに入れない。

## 10. エラー処理

| 状況 | 動き |
|---|---|
| 合言葉が違う | 記録せず `ERROR: 合言葉が違います` を返す |
| 有効な行が0件 | 記録せず `ERROR: 有効な測定がありません` を返す |
| シートや設定が足りない | ①はエラー文を返す。②は何が足りないかと直し方を表示する |
| 予期しない例外 | ①は `ERROR: ` に続けて例外の内容を返す。②はエラー画面を表示する。どちらも `console.error` に記録する |

## 12. ファイル構成

```

  ingest/appsscript.json   … タイムゾーン Asia/Tokyo、Webアプリ設定（全員）

  dashboard/Page.html      … 計器盤ページ（HTML・CSS・SVG描画のJavaScript）
```
